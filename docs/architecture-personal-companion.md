# 개인 지혜 동반자 (Personal Wisdom Companion) — 아키텍처 v0.1

> **목적:** 코덱스(또는 다른 리뷰어) 검증용 설계 문서.
> 핵심 질문: 이 아키텍처가 (1) 사용자 일상에 실제로 가치를 주는가, (2) 기술적으로 합리적인가, (3) 단계별로 검증 가능한가.

---

## 1. 한 줄 요약

성경 + 내가 가진 책 + 내 10년치 옵시디언 노트를 한 RAG 시스템으로 묶고, 일상 시점/감정 입력에 맞는 통찰을 꺼내주는 **나만을 위한 영적 동반자**.

## 2. 왜 만드는가 (Problem Statement)

### 지금까지의 실수
- "범용 묵상 앱"을 만들고 있었음 (다른 사람들 기준)
- 정작 만드는 본인이 일상에서 안 씀 → dogfooding 실패 → 진짜 가치 검증 불가

### 진짜 문제
- 말씀을 잘 읽고 싶은데 일상의 흐름과 단절됨
- 책 수천 권 있지만 필요한 순간에 못 꺼냄 (DEVONthink, 옵시디언에 잠들어 있음)
- 푸시 알림은 받지만 영양가 없음 (그냥 "성경 읽으세요" 수준)
- 힘들 때 위로받을 곳이 추상적

### 원하는 것
- 성경 읽을 때 내 서재에서 관련된 부분이 자연스럽게 떠오름
- 하루 중 수시로 의미 있는 푸시 (시점·맥락·감정에 맞는 구절+해설)
- "지금 어때?" 묻고 답하면 **내 자료에서** 답이 나옴 (성경/책/내 과거 노트)
- 비슷한 상황의 간증·영상 추천

## 3. 핵심 사용자 시나리오 (3개)

### S1. 아침 — 큐레이션된 푸시
```
[07:00] "오늘 새벽엔 시 42편을 권하고 싶어요. 작년 4월 17일에
        '갈증'이라는 단어를 8번 썼던 게 떠올라서요.
        바빙크는 이 시편의 '목마른 사슴'을 [...]"
```
→ 누르면 본문 + 내 과거 노트 발췌 + 책 인용 1~2개

### S2. 점심 — 즉석 상담
```
사용자: "회의 끝나고 자존감 박살났어"
시스템: "비슷한 감정을 2017년 11월에 적으셨네요. 그때 결론을
        이렇게 내렸어요: '내 정체성은 [...]'.
        칼빈은 자기지식과 하나님지식이 [...] 이 말을 잠시 묵상해
        보세요. 시 139편 1-6절."
```

### S3. 저녁 — 성경 깊이 읽기
```
요한복음 1장 읽는 중 → "말씀이 육신이 되어"에 머무름
→ 옆 패널에 자동으로:
   - 바빙크 4권 성육신 단락 (2 chunks)
   - 칼빈 기독교강요 II.13 (1 chunk)
   - 내 옵시디언 노트: 2019, 2022, 2024년 같은 구절 묵상 (3개)
```

### 5.1 핵심 설계 결정

**A. 3개의 분리된 컬렉션 (테넌트가 아니라 스토어 분리)**
- 성경/책 → 클라우드 Supabase (인터넷 어디서든 접근 가능)
- 옵시디언 → **로컬 전용** (집 맥/시놀로지에서만)
- 이유: 사적 데이터 노출 차단. 옵시디언은 외부 SaaS에 절대 안 보냄.

**B. 검색 전략: 다층 RAG**
```
질문 → 의도 분류 (chat/read/morning)
     ├─ "감정/상담" 의도면: 옵시디언 가중치 ↑, 책 보조
     ├─ "성경 읽기" 의도면: 성경 펼친 구절 기준으로 책+노트 동시 검색
     └─ "푸시 큐레이션" 의도면: 시간/요일/직전 메모 컨텍스트 사용
```

**C. 응답 합성: Claude + 캐싱**
- 검색 결과(top-k=5~10) → Claude Sonnet으로 합성
- 시스템 프롬프트(스타일/말투) 캐싱으로 비용 절감
- 매일 응답 캐시 (같은 질문에 다른 답 안 나오게)

**D. 인터페이스: 단계별 점진**
- v0.1: CLI/스크립트 (오늘 묵상 던지기, 챗봇 REPL)
- v0.2: iOS Shortcuts + 푸시 (Pythonista 또는 시놀로지 cron + Pushover)
- v0.3: 텔레그램 봇 (어디서든 챗)
- v1.0: 네이티브 앱 (지금 만들던 거 재활용)

## 7. 푸시 알림 시스템

### 후보 1: Pushover + 시놀로지 cron (추천)
- 시놀로지 NAS에 Python 스크립트 배포
- cron: 매일 07:00, 12:30, 19:00, 22:00 트리거
- 각 시점에 어울리는 큐레이션 스크립트 실행 → Pushover API로 푸시
- 장점: 24/7 가동, Mac 안 켜져 있어도 됨, $5 일회성

### 후보 2: iOS Shortcuts + Pythonista
- iPhone 안에서 완결, 외부 의존 최소
- 단점: 백그라운드 실행 제약, 옵시디언 RAG 접근 어려움

### 후보 3: 텔레그램 봇 + cron
- 챗 인터페이스 + 푸시 둘 다 됨
- 봇 토큰만 있으면 어디서든 양방향

**권장:** 후보 1 + 후보 3 조합. 푸시는 시놀로지에서, 챗은 텔레그램 봇으로.

## 8. 단계별 로드맵 (Dogfooding 우선)

| 단계 | 기간 | 목표 | 검증 기준 |
|---|---|---|---|
| **0. 기반 정리** | 완료 | 성경+책 RAG | 기독교강요 태깅 끝남 |
| **1. 옵시디언 RAG** | 1주 | vault 인제스트 + 검색 가능 | CLI에서 "지금 어때?"에 내 노트 인용 답변 |
| **2. 통합 챗 (CLI)** | 1주 | 3 소스 동시 검색 + Claude 합성 | 매일 1회 이상 직접 사용 |
| **3. 푸시 1단계** | 1주 | 시놀로지 cron + Pushover | 4번/일 의미 있는 알림 도착 |
| **4. 텔레그램 봇** | 2주 | 양방향 챗, 컨텍스트 유지 | 외출 중에도 사용 |
| **5. 모닝 다이제스트** | 1주 | 매일 아침 큐레이션 메일/푸시 | 7일 연속 읽음 |
| **6. 네이티브 앱** | 4주+ | 지금 만들던 앱에 백엔드 연결 | 본인 + 1명 베타 사용 |

각 단계 끝에 **"내가 일주일간 매일 썼는가?"** 체크. NO면 다음 단계 안 감.

## 10. 검증해야 할 가정 (코덱스에게 물을 것)

1. **3 소스를 별도 DB에 두는 게 맞는가?** 하나의 pgvector + namespace로도 충분한가? (사적 데이터 분리 vs 합성 효율)
2. **응답 합성 시 Claude만 쓰는 게 맞는가?** 매번 LLM 호출은 비싸고 느림. 캐싱 전략이 적절한가?
3. **옵시디언 인제스트가 정말 Haiku로 충분한가?** 신학 텍스트와 다르게 본인 글이라도 추상적·시적이면 분류가 어려울 수 있음.
4. **푸시 시점·내용 큐레이션 알고리즘**: 시간대 + 직전 노트 + 무작위? 기준이 너무 단순한가? 사용자가 1주일 만에 무뎌지지 않을까?
5. **에코챔버 위험**: 본인 노트 비중을 가중치로 강제 제한해야 하나? 아니면 사용자가 신뢰하는 외부(성경/책) 비중을 명시적으로 끌어올려야 하나?
6. **개인정보 보안**: 옵시디언 RAG가 로컬이어도 챗 응답은 Claude API로 나감. 검색 결과 텍스트가 Anthropic 서버로 전송되는데 이걸 받아들일 수 있는가? (대안: 로컬 LLM. 단, 품질 ↓)
7. **인터페이스 우선순위**: CLI → 푸시 → 텔레그램 → 앱 순서가 맞는가? 텔레그램이 dogfooding엔 더 빠르지 않나?
8. **단계 1 (옵시디언) 끝나고 2 (통합 챗) 가는 사이에 사용자가 매일 안 쓰면 어떻게 하는가?** 중단 기준 명확한가?
